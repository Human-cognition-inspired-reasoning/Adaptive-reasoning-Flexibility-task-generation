초안 2026-10-26, 확정 2026-10-26. **이 확정본을 커밋한 뒤 본 실행을 시작한다.** 이후 결과를 보고 판정 기준, 지표, 세션, 설정을 바꾸지 않는다.
v30(9×9)·v31·v32(40세션) 결과와 판정은 보존한다. 설계·지표·가설은 `PREREGISTRATION_V32.md`와 같고, 바뀌는 것은 세션 수와 모델 집합이다.

## 1. 표본 크기 변경 사유

과제 요건상 평가 데이터의 단위가 세션이며, 미로 300개로 300세션을 생성해 그중 100세션을 사용하는 것이 요건임이 확인되었다(연구 책임자,
2026-10-26). v32는 40세션(피드백) + 4세션(기준선)으로 판정을 마쳤으므로, 이 변경은 결과를 본 뒤 표본을 늘리는 것이다. 40세션 판정본
(`results/earlier_runs/v32_12x12_40_VERDICT.md`)은 별도 파일로 보존한다.

## 2. 범위: 12×12만, 9×9 제외

9×9(v30)는 재실행하지 않는다. 사유: (1) v32에서 미로 크기가 난이도 축으로 작동하지 않음이 확인되어(12×12 − 9×9 지속적 오류율·적응 성공률
차이 구간이 두 모델 모두 0을 포함) 두 크기를 모두 확장할 필요가 없다. (2) 12×12는 호출별 응답 시간(api_seconds)을 포함해 참조 형식 지표 표의
모든 열을 채울 수 있다(9×9의 claude-opus-5-5·claude-opus-5 기록에는 응답 시간이 없다).

## 3. 세션 (`generation/gen_v32_300.py`)

- v32 채택 12×12 미로 300개(채택률 0.268) 각각에 세션 하나, 300세션. 한 미로에 여러 세션을 두지 않는다(같은 미로의 세션은 독립 표본이 아니어서
  세션 단위 신뢰구간이 좁아진다). 미로 추가 생성 없음.
- 기존 40세션은 s00–s39로 그대로 두고 s40–s299를 덧붙였다. 시작 색은 블록마다 고르게(최대 유량 배정): s00–s99 색마다 25, 전체 색마다 75.
- **실험에 쓰는 세션: s00–s99**(`data/sessions100.json`), 그중 기존 40세션 비율 0.40. s100–s299(200세션)는 비공개 분할로 남긴다.
  (공개 시점의 주: 생성기가 시드로 고정되어 있어 공개 코드로 300세션 전체가 재현된다. 따라서 이 200세션은 더는 비공개가 아니다. `README.md` 참조.)
- 기준선 10세션: s00, s01, s02, s17(기존) + s40, s41, s42, s43, s52, s59(새로); 시작 색 blue 3, green 3, red 2, yellow 2.

## 4. 모델, 설정, 실행

- 모델 다섯: gpt-6.1-sol, gpt-5.6-luna, gpt-5.6-sol, claude-opus-5-5, claude-opus-5. T = 15, k = 3, 규칙 NB·AV·VIA, 목표·규칙 미고지, 정답/오답
  피드백만. 출력 상한 gpt-6.1-sol 4,096, gpt-5.6-luna 12,288, gpt-5.6-sol 12,288, claude-opus-5-5 8,192, claude-opus-5 20,480(스트리밍).
- **기존 실행 재사용**: gpt-6.1-sol과 claude-opus-5-5는 v32 본 실행(s00–s39 피드백, 기준선 s00·s01·s02·s17)을 그대로 쓰고 s40–s99 피드백과
  새 기준선 6세션만 추가로 돌린다. gpt-5.6-luna(2026-10-26 중단된 부분 실행은 쓰지 않음), gpt-5.6-sol, claude-opus-5는 s00–s99 피드백과 기준선
  10세션 전부를 새로 돌린다.
- 실행 순서: gpt-6.1-sol → gpt-5.6-luna → claude-opus-5-5 → gpt-5.6-sol. [예산 관련 절은 비공개]
- **claude-opus-5는 네 모델이 끝난 뒤 따로 결정한다(결정 2026-10-26).** 사유: 9×9에서 합산 거부율 18.2%로 정지 기준을 넘었고, 이번에는 사후 해제를
  하지 않는다. [예산 관련 절은 비공개] **이는 결과를 보고 모델을 고르는 것이 아니라 정지 위험에 따른 실행 순서 결정이다.** 등록 모델은 다섯이며,
  claude-opus-5를 끝내 돌리지 않으면 판정 시점에 그 사실과 사유를 적고 네 모델로 판정한다(v30 사전 등록 4절과 같은 원칙). 돌리게 되면 설정·세션·
  판정 기준은 이 문서 그대로다.
- 거부 처리와 정지 기준: `PREREGISTRATION_V32.md` 4절 그대로. 거부(Anthropic refusal)와 OpenAI 요청 차단(HTTP 400 invalid_prompt)은 시도로
  세지 않고 같은 시도를 피드백 없이 다시 요청하며, 5회 연속이면 시도 1회로 세고 지표에서 뺀다. 정지 기준은 모델 단위 합산 거부율(두 종류 합산)
  10%, 호출 100회 이상부터. **사후 해제하지 않는다.** 정지하면 부분 데이터를 보존하고 그 모델은 판정에서 제외한다. invalid_prompt 건수는 거부와
  별도로 보고한다.
- 기록 항목: `PREREGISTRATION_V32.md` 4절. 첫 모델의 첫 단계에서 확인하고, 빠진 항목이 있으면 멈춘다.

## 5. 지표, 가설, 판정 (v32와 같음)

- 지속적 오류율, 보조 지표, 실패 유형, 거부율은 `PREREGISTRATION_V32.md` 5절. H1–H3과 판정 기준은 6절과 같다. 신뢰구간: 세션 부트스트랩 1000회,
  시드 0, 피드백은 시작 색별 층화(색마다 25), 기준선은 층화 없음(10세션).
- H2는 H1 통과 모델이 둘 이상일 때만 판정한다. 통과 모델 수를 명시한다.
- 적응 성공률 0.5 미만 모델(gpt-5.6-luna 예상)은 완화 없이 표기하고 미도달 전환 수를 보고한다.

## 6. 실행 시점 점검 (판정과 별개)

재사용한 두 모델(gpt-6.1-sol, claude-opus-5-5)은 기존 s00–s39(2026-10-24·25 실행)와 추가 s40–s99의 지속적 오류율, 적응 성공률, 라운드당
시도를 따로 내고 차이와 95% 구간(독립 재표집)을 보고한다. 세 새 모델도 같은 분할로 차이를 내어, 두 블록 사이의 미로 표본 차이가 얼마인지
기준으로 삼는다(같은 시점에 돌린 모델의 블록 차이 = 미로 표본 차이, 재사용 모델의 블록 차이 = 미로 표본 차이 + 시점 차이).

## 8. 변경 (결정 2026-10-26, 본 실행 시작 전; 이 절이 1–7절의 해당 내용을 대체한다)

- **대상 모델을 셋으로 바꾼다: gpt-6.1-sol, claude-opus-5-5, claude-sonnet-5.** gpt-5.6-luna와 gpt-5.6-sol은 이번 범위에서 제외한다. 두 모델의
  기존 기록(9×9 v30 본 실행, 12×12 v32 예비 호출, gpt-5.6-luna의 2026-10-26 중단된 12×12 부분 실행)은 그대로 보존하며, 이 100세션 판정의 대상에서
  빠진다. claude-opus-5도 이 범위에 없다. claude-sonnet-5는 새로 추가한다(이전 과제에서 응답 길이 중앙 17,712, 최대 51,942로 고정 상한 측정이
  불가하다고 결론 났으나, 미로 과제에서는 측정한 적이 없어 예비 호출로 먼저 확인한다).
- **추론 노력 수준을 세 모델 모두 medium으로 명시 지정한다**(OpenAI `reasoning_effort`, Anthropic `output_config.effort`; 원자료 `api.effort`에
  기록). 지금까지는 API 기본값을 쓰는 원칙이었고, 이전 버전에서 claude-opus-5-5의 기본값이 medium이며 다른 Claude 모델 설정(high)과 다르다는 점을
  설정 차이로 기록한 바 있다. 이번에는 모델 간 비교를 위해 medium으로 지정한다. **이는 기본값을 쓰던 기존 원칙에서 벗어나는 것이며, 그 결과 기존
  40세션 실행(추론 노력 미지정)과 설정이 달라진다.**
- **기존 40세션 재사용 불가 → 세 모델 모두 100세션 + 기준선 10세션 전부 새로 돌린다.** 기존 v32 실행에서 실제로 적용된 추론 노력 수준을 확인할
  수 있는지 보았다. 원자료(`api` 필드: 토큰, 응답 모델, 종료 사유 등)와 설정 파일(`"temperature": "API default (not sent)"`)에 추론 노력 수준이
  남아 있지 않고, API 응답에도 적용된 수준이 들어 있지 않다. 문서상 claude-opus-5-5의 기본값은 medium이지만 실제 적용 값을 원자료로 확인할 수
  없으므로 재사용하지 않는다. 따라서 6절의 블록 비교(재사용 모델의 시점 효과)는 하지 않는다. 대신 세 모델 모두 같은 시점·같은 설정으로 돌린
  s00–s39와 s40–s99의 블록 차이를 미로 표본 차이로 보고한다.
- **진행 중이던 gpt-6.1-sol 실행(추론 노력 미지정, s40–s99)은 2026-10-26 11:48:20에 중단했다.** 부분 데이터(피드백 540호출, 기준선 150호출)는
  비공개 저장소에 보존하며 판정에 쓰지 않는다.
- **예비 호출을 세 모델 모두 다시 한다**(추론 노력 medium; 출력 길이와 라운드당 시도가 달라질 수 있어 기존 상한을 쓰지 않는다). 12×12 피드백
  2세션(s03, s05)을 끝까지, T 25, 출력 상한 128,000(Claude는 스트리밍). claude-sonnet-5는 예비 호출 30회 이상(분산이 큰 이 모델은 10회로는 평균
  추정이 불안정했다). 출력 상한은 관측 최대의 2배 이상으로 정하고, 128,000에서 끝나지 않은 호출은 건수와 조건을 보고한다. [예산 관련 절은 비공개]
- 설정·거부 처리·정지 기준(invalid_prompt 합산, 사후 해제 없음)·지표·가설은 1–7절 그대로다.

## 9. 확정 (결정 2026-10-26, 본 실행 시작 전)

- 예비 호출(추론 노력 medium; 세션 s03·s05, T 25, 상한 128,000, 128,000에서 끝나지 않은 호출 없음; 기록은 비공개)로 정한
  **출력 상한: gpt-6.1-sol 4,096(관측 최대 1,384의 3.0배), claude-opus-5-5 12,288(4,261의 2.9배), claude-sonnet-5 61,440(29,616의 2.1배)**.
  Claude 두 모델은 스트리밍으로 호출한다.
- **T = 15, 세 모델 모두.** claude-sonnet-5의 예비 호출 라운드당 시도는 12.12로 기준 12를 넘으나, T를 모델마다 다르게 하면 설정이 달라져 비교가
  끊긴다. 예상 적응 성공률 0.75(15시도 안 도달 비율)는 완화 없이 그대로 표기하고 미도달 전환 수를 함께 보고한다.
- **실행: 세 모델 모두 100 + 10세션을 새로 돌린다(추론 노력 medium).** (중단된 부분 실행과 섞지 않는다.) 공개 저장소의 `raw/`가 이 실행의 원자료다.
- 순서 gpt-6.1-sol → claude-opus-5-5. [예산 관련 절은 비공개]
- **claude-sonnet-5는 두 모델이 끝난 뒤 따로 결정한다.** 사유: 100세션 동시 실행 시 단계마다 가장 느린 응답(예비 호출 최대 294초)을 기다려 10시간
  안팎이 걸리고, 적응 성공률이 0.75로 세 모델 중 가장 낮다. [예산 관련 절은 비공개] **이 보류는 결과를 보고 모델을 고르는 것이 아니라 실행
  조건에 따른 실행 순서 결정이다.** claude-sonnet-5를 끝내 돌리지 않으면 판정 시점에 그 사실과 사유를 적고 두 모델로 판정한다(v30과 같은 원칙).
  돌리게 되면 설정·세션·판정 기준은 이 문서 그대로다.
- 블록 점검(6절 대체, 8절): 세 모델 모두 같은 시점·같은 설정으로 돌리므로 s00–s39와 s40–s99의 차이는 미로 표본 차이다. 모델마다 그 차이와 95%
  구간을 보고한다.

## 10. claude-sonnet-5 추가 실행 (결정 2026-10-27, 본 실행 시작 전)

- 보류했던 claude-sonnet-5를 세 모델 구성을 완성하기 위해 추가한다. 세션(s00–s99 피드백, 기준선 10세션), T 15, k 3, 규칙 셋, 목표·규칙 미고지,
  정답/오답 피드백만, 추론 노력 medium, 출력 상한 61,440(스트리밍)은 9절 그대로다.
- [예산 관련 절은 비공개] 거부 처리와 정지 기준(invalid_prompt 합산, 합산 10%, 호출 100회 이상부터, 사후 해제 없음)은 9절 그대로다.
