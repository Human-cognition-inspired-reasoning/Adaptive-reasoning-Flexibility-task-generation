# 사전 등록: v32 미로 과제 (12×12), 미지의 목표와 규칙

> **공개판.** 원본은 비공개 저장소에 그대로 보존한다. 공개판에서는 예산·비용 상한·승인 절차에 관한 문장을 빼고 그 자리에
> "[예산 관련 절은 비공개]"라고 적었다. 설계·세션·지표·가설·판정 기준·사후 변경 기록은 원본과 같다. 원본이 가리키던 비공개 문서(예비 호출
> 기록, 실행 메모 등)는 "(비공개)"로 표시했다.

작성·확정 2026-10-24. 이 문서를 커밋한 뒤 본 실행을 시작한다. 이후 결과를 보고 판정 기준, 지표, 세션, 설정을 바꾸지 않는다. 판정은 등록한 모델이
모두 끝난 뒤에 한 번 한다.

## 1. 목적

v30(9×9)에서 claude-opus-5-5와 gpt-6.1-sol의 적응 성공률이 각각 0.996으로 천장에 가까웠다. 미로를 12×12로 키워 난이도를 올렸을 때 지속적
오류율의 변별이 유지되는지 본다. **바꾸는 것은 미로 크기 하나뿐이다.** 그 밖의 설계, 지표, 가설, 판정 기준은 `PREREGISTRATION_V30.md`와 같다.

## 2. 과제 (v30과 같음, 크기만 다름)

- **미로**(`maze/loop.py: make_loop_maze_v30`, n = 12; `generation/gen_v32.py`): 깊이 우선 완전 미로 → 남은 내부 벽 4%(5개)를 2×2 열린 공간을
  만드는 벽은 건너뛰며 무작위 제거(고리). 벽 기둥 허용. 색 칸 넷은 통로 위(막다른 칸 제외), 서로 미로 거리 5 이상.
- **규칙 셋**: NB 되돌아가지 않기(이미 지난 칸에 다시 들어가지 않음) / AV 시작·목표 외의 색 칸을 지나지 않기 / VIA 다른 색 칸 하나 이상을 거치기.
  후보는 공개, 활성 규칙은 숨김. 시작은 알리고 목표는 "나머지 세 색 칸 중 하나"라는 사실만 알린다.
- **피드백**: "Correct." 또는 "Incorrect."만. **세션**: 8라운드, 전환 때 목표와 규칙이 모두 바뀜(직전과 같은 목표·규칙 금지). 연속 3회 성공(k = 3)이면
  전환, **라운드당 최대 T = 15시도**. 전환은 알리지 않는다. 제시는 목록 방식, 대화 기록 최근 10시도, 답은 마지막 `MOVES:` 줄.
- **거부 처리**: v30과 같다. 거부는 시도로 세지 않고 지표에서 빼며 같은 시도를 피드백 없이 다시 요청한다. 5회 연속 거부는 시도 1회("거부")로 세어
  라운드를 진행하고 역시 지표에서 뺀다.

## 3. 미로와 세션 (`data/v32/sessions.json`, `generation/gen_v32.py`로 재생성)

- 채택 조건은 v30과 같다(36조합 모두 해, NB·AV 정답이 갈리는 (시작, 목표) 쌍 하나 이상). 채택률 0.268(1,118개 중 300; 9×9 0.192). 정답 길이 중앙
  NB 18 / AV 20 / VIA 30(9×9: 13 / 14 / 22). NB·AV 정답이 갈리는 쌍 비율 0.264(9×9 0.249).
- 세션 40개(시작 색마다 10), 기준선 4세션(시작 색마다 1), 규칙·목표 순서 무작위(첫 시드 후보). 규칙 분포 AV 110 / VIA 105 / NB 105.
  H3 집단(라운드 2–8): 갈림 105, 갈리지 않음 175.

## 4. 조건과 모델

- 피드백 조건 40세션, 기준선 4세션(피드백 문장만 뺌).
- **모델과 순서: gpt-6.1-sol → claude-opus-5-5.** 등록 모델은 이 둘이다. 9×9에서 적응 성공률이 천장에 가장 가까웠던 모델이라 난이도 상승의 효과가
  가장 잘 드러난다.
- 설정: temperature 미전송, 사고·노력 수준 API 기본값, 대체 모델 끔. **T = 15**(9×9와 같음; T를 함께 바꾸면 크기 효과와 섞인다. 예비 호출의
  라운드당 시도 평균 claude-opus-5-5 5.75, gpt-6.1-sol 9.44로 기준 12 이내). **출력 상한 claude-opus-5-5 8,192, gpt-6.1-sol 4,096**(예비 호출
  관측 최대 3,245, 1,481의 2.5배, 2.8배; 세션 s03·s05, T 25; 기록은 비공개).
- 감시 기준은 v30과 같다: 모델 × 조건별 잘림 5%, 모델 단위 합산 거부율 10%(호출 100회 이상부터). [예산 관련 절은 비공개]
- 호출별 응답 시간(`api_seconds`)을 기록한다(예비 호출에서 243/243 기록 확인; 판정과 무관, 참조 형식 지표 표의 API time에 쓴다).
- **나머지 세 모델 추가(결정 2026-10-26)**: v30과 같은 다섯 모델 구성을 12×12에서 완성한다. gpt-5.6-luna, gpt-5.6-sol, claude-opus-5를 같은 세션
  (`data/v32/sessions.json`, 피드백 40·기준선 4)으로 추가하며 설계·세션·지표·판정 기준은 바꾸지 않는다. 예비 호출(세션 s03·s05, T 25, 상한
  128,000; 기록은 비공개)로 정한 출력 상한: gpt-5.6-luna 12,288(관측 최대 5,282의 2.3배), gpt-5.6-sol 12,288(4,536의 2.7배), claude-opus-5
  20,480(10,123의 2.0배, 스트리밍). T = 15(v30·v32와의 비교 유지; luna는 T 25에서도 연속 3회 성공 도달률 0.44이고 실패의 78%가 벽 통과라 T로
  해결되지 않는다).
  - **실행 순서**: gpt-5.6-luna → gpt-5.6-sol을 먼저 돌린다. [예산 관련 절은 비공개] **claude-opus-5는 두 모델이 끝난 뒤 따로 결정한다.** 9×9에서
    예비 호출 거부율 5.2%가 본 실행에서 18.2%로 올라 정지 기준을 넘었고, 이번에는 사후 해제를 하지 않는다.
  - **거부 정지 시 처리(실행 전 확정)**: 정지 기준은 v30과 같다(모델 단위 합산 거부율 10%, 호출 100회 이상부터). **사후 해제하지 않는다.** 기준에
    걸리면 실행을 멈추고, 그때까지의 부분 데이터는 보존하며, 그 모델은 H1–H3 판정과 9×9 비교에서 제외한다(수치는 "거부 정지, 판정 제외"로
    표기해 탐색용으로만 싣는다).
  - **OpenAI 요청 차단(invalid_prompt) 처리(결정 2026-10-26)**: OpenAI가 요청을 HTTP 400 `invalid_prompt`("your prompt was flagged as
    potentially violating our usage policy")로 거부하면 거부와 같은 방식으로 처리한다. 시도로 세지 않고 지표의 분자와 분모에서 빼며, 같은
    시도를 피드백 없이 다시 요청한다. 5회 연속이면 시도 1회("거부")로 세고 역시 지표에서 뺀다. 정지 기준(모델 단위 합산 거부율 10%)에도 거부와
    합산한다. 근거: 같은 미로 프롬프트가 9×9에서 같은 모델(gpt-5.6-luna)로 4,283회 정상 처리되었으므로 간헐적 외부 판정이며, 모델의 응답이
    아니라 요청 단계의 차단이다. Anthropic의 refusal과 성격이 같다. 기록: 원자료 `api.refusal_kind = "invalid_prompt"`(백엔드
    `maze/backends.py`, 응답 모델 없음). 실행 중 발생 건수는 거부와 별도 항목으로 보고한다. 계기: 2026-10-26 gpt-5.6-luna 기준선 실행이 이
    오류로 중단되었다.
  - **적응 성공률**: gpt-5.6-luna는 0.3 안팎으로 예상된다. 0.5 미만이면 완화 없이 표기하고 미도달 전환 수를 함께 보고한다.
  - **기록 항목**: 호출마다 api_seconds, 입력·출력·추론 토큰, 요청·응답 모델, 재시도 횟수, 거부·잘림·응답 읽기 성공 여부, 세션·라운드·시도 번호,
    규칙과 목표, 판정과 실패 유형을 남긴다. claude-opus-5의 추론 토큰은 Anthropic API가 따로 보고하지 않으므로 "API 제공 안 됨"으로 표기하고
    추정하지 않는다.

## 5. 지표 (v30과 같음; 거부 시도는 모든 지표에서 제외)

- **주 지표: 지속적 오류율.** 라운드 i(i ≥ 2) 값 = 그 라운드 시도 중 (i−1)라운드의 (목표, 규칙)으로 유효한 시도 수 / 그 라운드의 실제 시도 수.
  세션 값 = 라운드 2–8 평균, 모델 값 = 세션 평균.
- 보조 지표: 적응 성공률, 라운드당 성공률, 적응 속도, 실패 유형 분해, 전환당 보속 시도 수, 규칙 쌍별 값. 거부율은 품질 기준과 별개로 보고.

## 6. 가설과 판정 기준 (v30과 같음)

신뢰구간: 세션 단위 부트스트랩 1000회(시드 0, 시작 색별 층화; 기준선은 층화 없이 복원 추출). 다중비교 보정 없음.

- **H1 피드백 사용**: 모델마다 피드백 − 기준선 지속적 오류율 차이의 95% 구간 상한 < 0이면 지지. H1 기각 모델은 H2·H3에서 뺀다.
- **H2 모델 변별**: H1 통과 모델 쌍의 차이(같은 세션 짝지은 재표집) 구간이 0을 포함하지 않으면 지지. H1 통과 모델이 둘 미만이면 판정 불가로 적는다.
- **H3 NB·AV 정답이 갈리는 라운드 효과(양측)**: H1 통과 모델마다 갈리는 라운드와 갈리지 않는 라운드의 지속적 오류율 차이 구간이 0을 포함하지 않는
  모델이 하나 이상이면 지지.

## 7. 9×9 결과와의 비교 (판정과 별개 항목)

판정은 6절로만 한다. 별도 절로 다음을 낸다: 모델별 지속적 오류율, 적응 성공률, 라운드당 시도를 9×9(v30 본 실행)와 12×12(v32)에서 나란히 제시하고,
크기 상승이 모델마다 다르게 작용했는지 수치로 보인다(모델별 12×12 − 9×9 차이와 부트스트랩 95% 구간; 두 크기는 세션이 달라 독립 표본으로 재표집).
세션과 미로가 크기마다 따로 생성되었으므로 이 비교는 크기 효과와 미로 표본 차이를 함께 담는다.

## 8. 한계 (등록 시점)

1. 예비 호출에서 claude-opus-5-5의 라운드당 시도가 9×9의 5.20에서 12×12의 5.75로 거의 변하지 않았다. 이 모델에는 미로 크기가 난이도로 작동하지
   않을 가능성이 있으며, 본 실행에서 천장을 벗어나지 못하면 크기 외의 난이도 축을 찾아야 한다. 반면 gpt-6.1-sol은 6.41에서 9.44로 늘어 크기
   효과가 뚜렷하다.
2. v30의 한계가 그대로 이어진다. 목표를 숨긴 설계에서는 지속적 오류율에 목표 탐색이 섞여 규칙 전환 비용이 과소 측정된다(v31 설계 점검). H2는
   H1 통과 모델이 둘 이상이어야 판정할 수 있는데, v30에서는 다섯 모델 중 하나만 H1을 통과했다. 등록 모델이 둘이므로 둘 다 H1을 통과해야 H2를
   판정할 수 있다.
3. 예비 호출은 모델당 2세션(16라운드)이라 T 충분성 추정의 오차가 크다. gpt-6.1-sol은 예비 호출에서 16라운드 중 2개가 15시도 안에 연속 3회 성공에
   도달하지 못했다.
